# Сайт вебверфь.рф — исходники

Статический сайт ВебВерфи: главная, страницы проектов, «Летопись верфи», «Для бизнеса», финмодель,
демо и кейсы. Живёт на проде в `/var/www/verf` (сервер `priemka`, nginx vhost `verf`).

**Этот репозиторий — источник правды.** До 15.11.2026 его не было: сайт правили прямо на сервере,
и любая перезаливка из локальных папок могла стереть правки (так чуть не случилось с пунктом «Блог»
в меню). Теперь порядок один: правим здесь, коммитим, выкатываем скриптом.

## Выкатка

```bash
deploy/site_deploy.sh          # изменённые файлы на прод, с бэкапом и смоуком
```

Что делает скрипт:

1. требует чистую рабочую копию и совпадение с `origin/main` — выкатывается только закоммиченное;
2. сначала сухой прогон: показывает, какие файлы изменятся, и ничего не делает, если изменений нет;
3. копирует файлы, которые будут перезаписаны, в `/var/www/verf/_backup_<дата>/`;
4. заливает сайт на сервер **без удаления** того, чего нет в репозитории (лишние файлы на сервере не трогаются);
5. проверяет, что главная, блог и страница проекта отвечают 200.

Откат — вернуть файлы из `/var/www/verf/_backup_<дата>/`.

## Что в репозитории и чего нет

| Есть | Нет |
|---|---|
| `*.html` — все страницы сайта | `blog/` — **генерируется** сборщиком из репозитория `vebverf-blog` (systemd `vebverf-blog-sync`, раз в 5 минут) |
| `img/`, `fonts/`, `cases/`, `demo/` | `*.bak_*` — резервные копии, их делает скрипт выкатки |
| видео и постеры в корне (`*_long.mp4` и т.п.) | `.well-known/` — выпуск сертификатов Let's Encrypt |

Блог живёт отдельно и в этот репозиторий не кладётся: его статьи и сборщик — в `vebverf-blog`,
на сервере они появляются сами.

## Что важно помнить про этот сайт

- Сайт — не одна страница: главная `index.html` и старые варианты (`site.html`) отличаются, при правке цен
  и офферов сверяйте обе. `site.html` сейчас отдаёт 301 на главную, но файл лежит и может понадобиться.
- Адреса внутри страниц абсолютные (`https://вебверфь.рф/...`), поэтому локальная копия без сервера
  выглядит «с чужого домена» — это нормально.
- Медиа и картинки лежат рядом с html, а не в подпапках вида `../media/`: так задумано, при переносе
  файлов из локальных папок пути ломались.
